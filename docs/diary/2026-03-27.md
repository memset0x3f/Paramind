## Addendum — shard dtype policy is now explicit instead of accidental

## Summary
今天把 `ShardConfig.dtype` 从“存在但没有真正进入执行路径的占位字段”收口成了真实生效的加载策略，而且语义从“无条件强制某个默认 dtype”调整成了“config 优先，不传时保留权重原生 dtype”。此前 full-model reference 可能落到 `float32`，而 shard loader 又因为直接接管 checkpoint tensor 常常变成 `bfloat16`；现在 shard 路径要么显式服从 `ShardConfig.dtype`，要么在 `dtype=None` 时沿用 safetensors 里原本的 dtype。

## Decisions made
这次没有删除 `dtype`，而是把它变成单一真相，但允许“不指定”。`ShardLoader` 现在会先尝试把 `float16 / bfloat16 / float32` 映射成 `torch.dtype`；如果 config 没指定，就从实际加载到的 state_dict tensor 推断 native dtype。然后 shell 创建和 layer/embed/norm/lm_head 的 materialize/cast 都服从这个最终目标 dtype。测试也同步收口成两类：一种验证非法 dtype 会被拒绝，另一种验证显式 `float32` config 真会得到 `float32` shard；而默认 CPU 路径则重新回到“不传 dtype，保留原生权重精度”的语义。
