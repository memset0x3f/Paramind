# Frontend development log — 2026-04-01

## Desktop renderer stabilization

### 1. General group participant count did not update when peers joined or left
- Symptom: `group · N participants` in the active `general` room stayed stale until a manual refresh, even though peer presence changed.
- Root cause: the default `general` conversation derives its participant summary from known peers, but peer lifecycle events only re-rendered the peer list. They never synchronized `general.participant_ids` in renderer state, so the active room shell kept old participant metadata.
- Fix: in `/Users/acropolis/Github_Project/Paramind/paramind/apps/desktop/renderer/chat.js`, add a local `syncDefaultGroupParticipantsFromPeers()` step and run it on `peer.joined`, `peer.updated`, and `peer.left`. If the active conversation is `general`, promote the render scope to `shell-list` so the room meta updates immediately.
- Verification: Playwright regression `general participant count tracks peer join and leave events without refresh` now passes.
- Remaining limitation: this local sync is intentionally scoped to the default `general` room because that room's participant model is peer-presence-derived; custom group membership still depends on explicit conversation lifecycle events.

### 5. Group invitation payload accidentally treated pending invitees as real members
- Symptom: when A created a group and invited B/C, B accepting caused C to see the group prematurely, even before accepting or while rejecting.
- Root cause: the backend stored `participant_ids_json` on each invitation as “current members + pending invitees”. Accepting one invitation therefore promoted other pending invitees into the participant set and broadcast `conversation.updated` with the wrong membership.
- Fix: in `/Users/acropolis/Github_Project/Paramind/paramind/apps/desktop/python/app/services.py`, keep invitation `participant_ids_json` scoped to the current accepted participant set only. The accepting peer is merged at accept time, instead of pre-seeding every pending target as a member.
- Verification: backend regression `test_group_invitation_accept_flow_creates_group_for_accepting_peer_only` now passes and confirms rejected / still-pending peers do not see the group conversation.
- Remaining limitation: invitation payloads no longer try to predict future membership; if the UI ever wants to show “invited but not yet joined” counts, that should come from pending invitation rows rather than `participant_ids`.

## Streaming text contract — 编号后乱码（UTF-8）与累计文本

### 10. 列表编号后出现 `�` / 中文缺字（流式 delta 与 tokenizer 边界）

- Symptom: 模型回答里编号列表（如 `1.`）后面偶发替换字符或缺字（例如「光速」变成「速」），像编码损坏。
- Root cause: `InferenceEngine.generate_stream` 曾按 **增量** 输出 `new_text[len(decoded_so_far):]`。对 ByteLevel BPE 等 tokenizer，**整段 `decode` 可能修正前段边界**，`decoded_so_far` 不一定是 `new_text` 的前缀，按 **Python 字符串长度** 切片会把多字节 UTF-8 切断，拼接进 UI 后出现 U+FFFD 或错字。
- Fix:
  - **推理层**：`LocalInferenceEngine` / `DistributedInferenceEngine` 的 `generate_stream` 每步 **yield 当前完整累计 decode 字符串**（仅在 `new_text != decoded_so_far` 时 yield）；删除循环后多余的 **flush**（与累计语义重复）。
  - **一次性 `generate()`**：改为取流式 **最后一次** yield，不再 `"".join(stream)`（否则会把各步整段重复拼接）。
  - **Desktop backend**：`InferenceRunner` / `services.py` 中变量统一为 `cumulative_text`；`message.token` 事件 payload 字段名仍为 `token`，值为 **该步完整累计正文**。
  - **Renderer**：`message.token` 与 `chat_state` 更新 **整段替换** `content`，不再把 payload 当 delta 拼接；`appendTokenToDraft` 重命名为 **`setDraftAssistantContent`**；浏览器 harness 中 `appendAssistantToken` 重命名为 **`setAssistantDraftContent`**，演示按钮文案改为「Simulate AI stream」。
- Files changed: `inference/InferenceEngine.py`, `inference/DistributedEngine.py`, `paramind/apps/desktop/python/app/inference.py`, `paramind/apps/desktop/python/app/services.py`, `paramind/apps/desktop/renderer/chat.js`, `paramind/apps/desktop/renderer/chat_state.js`, `paramind/apps/desktop/renderer/dev_harness.js`, `test/backend/test_runtime_selection.py`（Fake 引擎累计 yield）, `test/backend/test_chat_state.mjs`, `test/backend/test_renderer_harness.mjs`, `test/backend/test_renderer_harness.spec.mjs`, `test/inference/test_decode_streaming.py`（模块说明：diff 实验 vs 生产累计语义）, `docs/diary/frontend/2026-03-27.md`（函数名同步）
- Verification: `node --test test/backend/test_chat_state.mjs` 与 `node --test test/backend/test_renderer_harness.mjs` 通过；`pytest test/backend/test_runtime_selection.py` 在具备 `torch` 的环境下应通过。
- Remaining limitation: 事件仍名为 `message.token` 且 payload 键为 `token`，语义已是 **full cumulative**；若对外部集成者暴露 API，建议在文档中明确，避免仍按 delta 拼接。
