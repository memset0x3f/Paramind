## Addendum — shard lifecycle execution now runs through prepare/commit

### Summary
第三批把 reconfiguration 从 metadata/payload 再推进了一层：`keep` / `load` / `move_in` / `unload` 现在已经开始驱动节点本地 shard 生命周期与 coordinator barrier，而不只是当作 planner diff 展示。

### Decisions made
这一轮固定采用两阶段协议：先 `cluster_reconfigure_prepare`，后 `cluster_reconfigure_commit`。`move_in` 在 v1 里不做 peer-to-peer 权重传输，而是目标节点本地 reload shard；`unload` 在 prepare 阶段只能标记 `pending_unload`，commit 之后才真正释放。这样优先保证 prepare-before-unload 的控制面正确性，而不是一次性追求所有运行期细节。

## Addendum — runtime safety core now includes inflight, draining, and snapshots

### Summary
又往前推进了一步：现在 reconfiguration 不只是 prepare-before-unload，而是已经开始具备最小运行期安全语义。old owner 在 commit 后如果仍有 inflight 请求，会转成 `draining`；new owner 会立即进入 `serving` 并接新请求。

### Decisions made
这一轮没有继续改 planner，也没有碰 `p2p/` 的 retry / transport recovery。重点只放在 `inference/`：给 shard record 增加 inflight/timestamp 字段，给 runtime 增加 request enter/exit accounting 和 delayed release，并给 runtime/coordinator 都补上 `debug_snapshot()` 观测面。这样做的好处是，系统现在不但更安全，而且可诊断。
